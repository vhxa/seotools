## PostgreSQL 17: transfer blocked before upgrade

A throwaway PostgreSQL 17 container, named volume and isolated Docker network were started.
The published 0.3.0 image's supported `migrate-db.mjs --from file:… --to postgres:…` command
was attempted against the 0.3.0 online backup. The source file was bind-mounted read-only.
The CLI exited **1** with:

```text
attempt to write a readonly database (SQLITE_READONLY_DIRECTORY)
The copy failed. Drop the PostgreSQL database, create it again empty and retry; the SQLite database was not changed.
```

This is a harness mount limitation: SQLite sidecar creation needs a writable directory even
when the source data is to be read. It is not evidence of a PostgreSQL migration defect.
No retry or fallback seed followed because the SQLite target worker had failed concurrently.
PostgreSQL baseline counts, schema journal hashes, health, upgrade timing, reanalysis, authenticated
pages and downgrade behavior are all **unverified**.
